## Решения владельца, которые действуют дальше

- Проверку потреблением человеку не передаём; прогон на агентах ещё будет,
  но не сейчас (слово владельца 2026-10-23). R8 и всякий внешний опыт — только
  по слову владельца. Комплект — `tool/consumer_validation/`, порядок прогона —
  `docs/consumer-validation.md`, прошлый прогон —
  `docs/records/2026-10-23[8]-consumer-validation-report.md`.
- Ломающая правка, включая переименование и новый вариант публичного enum,
  требует минимум минорного бампа у 0.x. Перед переименованием скажи это
  владельцу. Публикация — только отдельная связка по `AGENTS.md` §5.
- `listen`/`select` на `Listenable` живут во втором импорте,
  `package:scopo/listenable.dart`, а не в главном (0.18.0, «давай перенесём»;
  «удалить совсем» отвергнуто): в главном они конфликтуют
  с `package:flutter_solo/listenable.dart`. Держит
  `test/listenable_import_test.dart`, разбор —
  `docs/records/2026-10-23[12]-listenable-import-design.md`.
- Смена владеющего конструктора на `.value` у `ScopeModel`/`ScopeNotifier`
  запрещена ассертом. `State.dispose` у `LiteScopeState`/`ScopeState` закрыт
  от переопределения; синхронный разбор — в `onUnmount`.
- Присваиваемый колбэк — короткий глагол, переопределяемый хук — `onX`. Ассерты
  с объяснением и советом оформляй через `FlutterError.fromParts`.
- Ручная инициализация защищается `catch`, без флага: отмена бросает
  `Cancelled` из контрольной точки. `disposeScope` вызывается только после
  успешного `initScope`; частичная уборка — внутри его `catch`.
  `disposeStateAsync` выполняется и после сбоя `initStateAsync`.
- Зависимости на `async_job` заново не переводить: это обход, не набор задач.
  Решение — `docs/records/2026-09-09[7]-dependency-job-design.md`.
- Отказ без адресата отчитывается, а не бросается; вызывающий `close` слышит
  ошибку. `Cancelled` из `dep.dispose` и `ctx.onDispose` не даёт отчёта
  в `FlutterError`. Отдельного отчёта в `_settleFailure` не заводить: ошибка
  тела уже показана через `errorBuilder`.
- `ScopeTimeout.none` имеет единый смысл; бессмысленные места отвергают его
  ассертом. Отрицательный `Duration` — отказ. `ScopeConfig.reset` возвращает
  переключатели к умолчаниям, наблюдателя не трогает.
- Виджет удерживается до конца брошенной инициализации, чтобы поздний ресурс
  получил освобождение. Два этапа разбора у `Scope` ограничиваются отдельно
  (`boundsDisposeScopeItself`). Повторно поданный узел зависимостей отвергается
  только ассертом; в release пропускается намеренно.
- Подписка допустима из своей сборки или билдера, перезапускаемого целиком;
  item-билдер ленивого списка требует `Builder` вокруг ячейки. Зависимый,
  перестроенный дважды за кадр, сохраняет оба набора селекторов: цена — одна
  лишняя сборка. `data` доступно до ready намеренно, для `disposeScope`.
- `ScopeController` не инициализируется после разбора; разбор один, исход общий
  для всех вызвавших. `notifyDependents` обновляет подписчиков, `setState` —
  собственный `build`; это разные действия.
- Ссылки на темы из README ведут на pub.dev; имена тем —
  из `dartdoc_options.yaml`. Скриншоты технического демо не добавляем. Сьюта
  демо входит в публикуемый архив намеренно, как образец тестирования.
  Комментарии примеров в русских зеркалах тоже переводятся (`AGENTS.md` §7).
- `controllerDep` сохраняет `mounted` контроллера до конца инициализации;
  отмену проверяют через `ScopeInitContext`. Инварианты семейств закрыты
  аннотациями; не-nullable `value` держит компилятор.

## Действующие границы и грабли

- Ядро после `onError` наблюдателя шлёт ошибку ещё и в зону, поэтому
  `_ScopeInitObserver` — `JobAnswerer`; без этого сбой доходит дважды, и видно
  это только прогоном.
- Ожидание `_initCompleter.future` не получило отдельного лимита по решению
  владельца: очередь за `scopeKey` будит `entry.cancel`, а инициализацию
  состояния снаружи ограничивает `disposeScopeTimeout`.
- Отсутствие `scheduleFrame` виджет-тест не видит: `pump` рисует кадр сам.
  `ScreenshotReplacer.onCompleted` приходит из post-frame callback, после
  размонтирования ребёнка: тесту, ждущему сигнал, нужен ещё один кадр, а при
  остановленных кадрах замену доводит warm-up кадр. Release-ветки за ассертом
  `flutter test` не проверяет.
- `_disposalIsOver` в `_prepareDependencies` нельзя заменять вторым шаблоном:
  предикат читает `_isDisposalDone`, а непрошедший шаблон провалится дальше.
- Обновление модели из раннего отказа `_performAsyncInit` — через
  `runOutsideFrame`; completer завершается раньше потенциально бросающего кода,
  иначе разбор повиснет. Ошибки отброшенного future ловит `runZonedGuarded`,
  а не `tester.takeException`.
- После `_disposalFinished` нельзя рассчитывать на `widget`: асинхронным
  отчётам нужна сохранённая метка. Для `close` нужна ненулевая фикстура:
  `ScreenshotReplacer` заменяет поддерево картинкой и размонтирует детей.
- Ассерт смены режима проверяют в `build`, не в `didUpdateWidget`: бросок
  из обновления может оставить поддерево неразобранным. Подменённый
  `FlutterError.onError` возвращают до `expect`, иначе он проглотит провал.
- Для таймаутов в виджет-тестах — общий `test/utils/settle.dart`; таймер
  разбора берут из `Zone.root`. Отрицательные ожидания снимают соседний лимит;
  single-subscription события требуют `tester.runAsync`.
- Не запускать два корневых тестовых прогона одновременно: они делят кеш. Чужой
  `flutter_tester` не убивать по имени: принадлежность доказывает родитель
  процесса. Мутации откатывать копией, не командами git.
- Анализатор не заменяет прогон при миграции. Если форматтер изменил код,
  повторить анализ; `--set-exit-if-changed` пишет файлы. Поиск — `git grep`,
  чтобы не читать старый `doc/api/`. Штамп перевода не проверяет его смысл.
- `tool/check_doc_examples.dart` держит все блоки Dart README и тем,
  по манифесту на документ в `tool/doc_examples/`. Восемь блоков пропущены
  с причиной в каждом прогоне — наброски с многоточием и выдержка API; среди
  них README `accessors-the-type-arguments-o/App`, и настоящие вызовы
  `App.access.select` в нём не проверяются. Имя, объявленное двумя блоками
  раздела, берётся ключом только с `shared: true`. `@override`, который ничего
  не переопределяет, стенд считает ошибкой: обёртки часто абстрактные.
  `example/README.md` сверяется с `example/minimal/lib/main.dart` байт в байт.
- XML-шаблоны не допускают `--` внутри комментариев; новый пакет в папке
  репозитория наследует его `.pubignore`. Рабочая копия сниппетов
  `.vscode/scopo.code-snippets` должна совпадать с `ide/scopo.code-snippets`.
